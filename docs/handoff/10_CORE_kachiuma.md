# 10_CORE_kachiuma 【凍結・編集禁止】思想・確定判断・変更手順

ここに書かれていることは、プロジェクトの土台であり後継モデルが書き換えてはならない。
現在の数値・タスク状態は 40_STATE が持つ（この文書には原則として数値を書かない）。

## 1. プロダクト思想（魂）

- 目的は「市場（オッズ）が見落とす3着内実力馬の発掘」。1番人気を当てても価値としない。
- 主役は「隠れ複勝候補」バッジ = 実力+騎手スコア上位なのに人気薄の馬。
  ◎○▲△は実力+騎手スコア順（方針b）で、市場と独立に付ける。
- サイトは正直に作る: 推定は推定と書く、単勝の数字は「単勝」と明記、実績は
  良い数字も悪い数字もそのまま出す、古い予想には古いと表示する。
- 「思い込みでなくバックテストで決める」「1週・1レースの結果で設計を変えない」
  「聞かれたら推測でなく実データで精査」。

## 2. 確定判断（覆すには proof 相当の検証 + ユーザーの明示合意が必要）

以下は検証の末に確定した判断。理由ごと記憶し、"良さそうだから"で戻さない。
覆した場合は 40_STATE の更新履歴に記録する（この文書は書き換えない）。

1. **市場との融合は棄却（LAMBDA=0）**: 実力を市場勝率に混ぜる融合はλ全水準で
   複勝率を悪化させた。p・EV は市場のみで算出する。
2. **着内実績ゼロの馬はクラス項で最下位評価**（中立0ではない）: 中立にすると
   未勝利戦で無実績馬が実績馬より上に浮上する（これが元のバグ）。
3. **格上挑戦ペナルティ（W_EDGE）は棄却**: スイープで改善せず。
4. **時間減衰（DECAY_HALF_D）は棄却**: スイープで一貫した改善なし。
5. **障害と平地のキャリアは分離**: 障害の格が平地の格に化けて汚染する。
6. **馬場表記は正規化して照合**（稍/稍重、不/不良）: しないと道悪日に馬場項が全滅する。
7. **バッジは条件戦以下のみ**（OP・重賞では非表示）: 重賞層は効果が不安定なため
   保守的に閉じている。解除は層別検証の母数が揃ってから。
8. **騎手表はレース日ごとに別物**: 集計期間が日付基準（当日を含めない）のため。
   複数日を跨ぐ再計算で単日用のメモを流用しない。

## 3. 変更の入れ方（不変の手順）

新しい重み・特徴量・ロジックは必ずこの順で入れる。飛ばさない。

1. **観測装置**: スコアを一切変えず、仮説の信号が実3着内率と相関するかを
   proof の出力に追加して観測する（層別・母数つき）。
2. **母数を貯める**: 複数窓で観測し、傾向が安定するのを待つ。
3. **既定OFFノブで実装**: 定数（重み）を既定0/None で追加し、
   **旧版と新版の出力が既定で完全一致**することを実データ（キャッシュの
   1000頭超×複数条件×騎手込み）で数値証明してから配布する。
4. **スイープ**: proof に候補値のスイープを追加して回す。
5. **採用3条件**: (a) 複勝率(指標A)・ベース比・複回収の**3つ全部**が現行(W=0)を
   上回る、(b) **複数窓（最低3〜4窓）で一貫**して同じ値が勝つ、(c) 差が1σ台なら
   観測継続、**迷ったら不採用**。満たして初めてユーザーに採否を諮る。
6. 採用が決まったら enrich 側に明示設定し、recompute で過去も打ち直して
   実績表示と本番を一致させる。

## 4. ユーザー環境と協働様式（不変の制約）

- ユーザーは **iPhone/Safari のみ**。開発機なし。
- ファイルは**全文貼り替え**で渡す（GitHub モバイルで貼る）。diff・パッチ・
  行指定の編集指示は使えない。複数ファイルは貼り替え順を明記する。
- 実行は GitHub Actions。ログはスクショまたはコピペで貼られる。
- 開発サンドボックスから netkeiba / umarengod / Chrome には**到達できない**。
  ライブ取得部分は「スタブでロジック検証 + 実物（Actions/サイト表示）で確認」の
  2段構え。実レスポンス構造が未確認の箇所は**推定と明記**し診断手段を添える。
- リポジトリ取得は codeload の tarball（SKILL.md 記載のコマンド）。

## 5. 検証の型（不変のパターン集）

- **完全一致検証**: importlib で旧版・新版を別名ロードし、実キャッシュから
  大量サンプル×複数レース条件×騎手込みで ability_probs の最大差==0 を assert。
- **冪等性**: 集計・再計算・バッジ付与は再実行で結果が変わらないことをテストする。
- **フロント検証**: Node で document/localStorage/fetch/Date をスタブし、
  `vm.runInThisContext` で index.html の JS を読み込むスモークテスト
  （require はスコープが閉じて不可。日時依存は Date をクラス継承でモック）。
- **yml 検証**: YAML 構文 + 埋め込み Python の compile + **全 run: ブロックに
  `${{` が無いこと**の3点セット（詳細は 30_PITFALLS A項）。
